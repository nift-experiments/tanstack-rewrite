# Publication SSR feasibility

The request-local router from the retained-shell proof wraps Nift-composed native article HTML in the byte-preserved Navbar and its providers. Each request owns a QueryClient and receives freshly validated, explicitly serialized session context; no session secret is serialized. The browser initializes article ownership from the live server DOM, not a parallel AST or stale article payload, and uses Router's SSR marker to preserve its initial boundary tree.

The publication compiler uses the pinned official Start compiler directly for isomorphic/client-only UI macros and generated RPC clients. RPC declaration modules use the official client transform so provider implementations stay out of this graph. It does not run the Start site-server plugin, backend compiler, original route generator, corpus parser or content-collections. Rspack retains the original source side-effect semantics. Its full nested/orphan manifest is audited by proof:publication-imports. This compiler API is pinned implementation-level integration, with an upgrade-maintenance cost, not a new general Start implementation.

Current serialization deliberately makes two passes over the same loaded request tree: first resolve retained lazy views, then renderToString. Streamed Router HTML still contained script-revealed segments after allReady in the rejected first attempt. The synchronous final output makes article/navigation visible with JavaScript disabled and must contain no unresolved Suspense template. Both passes are publication rendering work and must be included in later profiling and benchmarks. This is an initial correct implementation, not an optimization claim.

The browser proof holds the entry script, edits native server HTML, then verifies that hydration preserves both the edited text and exact node. It also exercises theme/search/mobile controls, Nift publication navigation/republication, and separate signed/anonymous requests with the retained account menu. Public external reads replay bounded fixtures. A single read-only controlled upstream GET oracle remains; provider/database/chat/full service and complete layout/route/SEO parity are not accepted by this proof. R3 remains open.
